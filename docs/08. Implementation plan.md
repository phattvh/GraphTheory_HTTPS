## 1.1. Quy ước môi trường phát triển: 100% Docker Images (Docker-First)

Toàn bộ thành viên **không cài đặt trực tiếp** PostgreSQL, Python/venv hay Caddy lên máy cá nhân (tránh lệch phiên bản và lỗi _"máy em chạy được, máy bạn lỗi"_). Mỗi máy chỉ cần cài duy nhất **Docker (Docker Desktop / Docker Engine)**, **Git** và **VS Code**:

| Thành phần               | Docker Image                                       | Cách dùng khi lập trình (Dev)                                                                                                                                                                                |
| ------------------------ | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **CSDL**                 | `postgres:16-alpine`                               | Tự chạy `db/init/init.sql` khi khởi tạo volume; thao tác SQL qua `docker compose exec postgres psql ...`                                                                                                     |
| **Backend & Thuật toán** | `python:3.12-slim` (build từ `backend/Dockerfile`) | Quản lý toàn bộ thư viện trong `backend/requirements.txt`; bind-mount `./backend:/app/backend` + `uvicorn --reload` để sửa code là tự nạp lại; chạy script test qua `docker compose exec fastapi python ...` |
| **Reverse Proxy & Web**  | `caddy:2-alpine`                                   | Bind-mount `./web:/srv/web` và `./Caddyfile`; Frontend sửa HTML/CSS/JS rồi F5 trình duyệt thấy ngay qua HTTPS                                                                                                |

## 4. Nguyên tắc phối hợp nhóm & Quản lý mã nguồn (Git Guidelines)

1. **Chiến lược phân nhánh Git (`Branching Strategy`):**
   - `main`: Nhánh sản phẩm chính, chỉ nhận code đã được kiểm thử ổn định thông qua Merge / Pull Request.
   - `test`: Nhánh dùng để gộp và kiểm thử tích hợp code trước khi đẩy lên `main` _(do người phụ trách quản lý)_.
   - Nhánh tính năng / sửa lỗi riêng biệt: Mỗi chức năng hoặc bug làm trên một nhánh riêng đặt tên rõ ràng:
     - `feat/<ten-chuc-nang>` _(VD: `feat/user-login`, `feat/dsatur-engine`)_
     - `fix/<ten-loi>` _(VD: `fix/room-capacity`)_
     - `test/<ten-chuc-nang>` _(VD: `test/user-login`)_
   - Luôn `pull` / `merge` code mới nhất từ nhánh gốc trước khi mở nhánh mới và trước khi merge ngược lại để hạn chế xung đột.
   - Xóa nhánh sau khi đã merge xong và không còn sử dụng.
2. **Quy tắc Commit, Kiểm thử & `.gitignore`:**
   - **Commit nhỏ, tách bạch:** Xong một chức năng hoặc phần việc nhỏ thì commit ngay, không gộp nhiều tính năng/sửa lỗi vào một commit.
   - **Làm tới đâu test tới đó:** Kết hợp test tay và viết file test tương ứng (VD: `<ten_chuc_nang>_test.py`), chạy pass hết rồi mới commit. Nếu dùng AI hỗ trợ test, mở một khung chat mới độc lập để tránh thiên vị.
   - **Dọn sạch trước khi commit & dùng `.gitignore`:** Xóa file tạm, code nháp, log thử nghiệm và không commit `.env`, cache (`__pycache__`, `.pytest_cache`).
   - **Tiền tố Commit Message (Conventional Commits):** Viết ngắn gọn, nêu rõ làm gì và vì sao:
     - `feat:` thêm chức năng mới _(VD: `feat: add login validation`)_
     - `fix:` sửa lỗi
     - `test:` thêm hoặc cập nhật file test _(VD: `test: add login_test.py`)_
     - `refactor:` chỉnh sửa code nhưng không đổi logic/chức năng
     - `chore:` dọn dẹp, cập nhật cấu hình hoặc file phụ
     - `docs:` cập nhật tài liệu
3. **Quy trình Daily Standup (Họp nhanh 10 phút đầu mỗi ngày):**
   - Mỗi thành viên trả lời nhanh 3 câu hỏi:
     1. Ngày hôm qua tôi đã hoàn thành nhiệm vụ nào?
     2. Ngày hôm nay tôi sẽ làm nhiệm vụ nào theo bảng kế hoạch?
     3. Tôi có đang gặp khó khăn/vướng mắc gì cần sự hỗ trợ của thành viên khác không?
